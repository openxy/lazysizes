# 精读：lazysizes.js（4.1.0，701 行——调度机制全家桶版）

与 v1 系列读的是同一个文件的两代。架构骨架（UMD → 工具层 → loader → autoSizer → 配置）一字未动，读这版抓三件事：**转正的三段调度、新增的可见性判断、配置面变化**。与 v1 重复的基础设施（类操作、事件、unveil 流程）不再重讲。

## 一、转正的调度全家桶

- **rAF 批处理升级为双队列**（112-149 行）：v1 的 rafBatch 只在 unveil 内部用，这里升级为全局 rAF：`firstFns`/`secondFns` 两个队列，执行中排进来的活进另一队列（134 行 `if(running && !queue)` 甚至让同步上下文插队直接执行）；后台标签页用 setTimeout 代替 rAF（141 行，rAF 在隐藏页面会停摆而检查还得跑）；`_lsFlush` 暴露成强制清空口（初始化后立即检查首屏，见 601-606 行）；
- **throttle 的 rIC 分支**（166-214 行）：对照 v1 的注释版（1.5.0 的 130-182 行）读，机制转正、参数打磨——`throttleDelay`（默认 125ms）与 `ricTimeout` 进配置；`isPriority` 提级把超时压到 33ms；剩余窗口不足 9ms 直接走空闲回调不再排队。没有 rIC 的浏览器回退 `rAFIt(setTimeout)`——**实验转正了，兜底也没丢**；
- **debounce 收编**（217-241 行）：99ms 防抖。onload 里的滚动档位切换（547-550 行）从 v1 的手搓定时器换成它——「停滚后再升档」的语义一句话就对了。

## 二、可见性与加载语义的补丁

- 394 行：`lazySizesConfig.loadHidden || getCSS(...'visibility') != 'hidden'`——loadHidden 配置（4.0.0 引入）：默认连隐藏元素也加载（保 CSS 特效），可关掉省流量。**把一个争议行为做成开关**，是成熟库处理用户分歧的惯用手法；
- 296 行：爬虫检测正则从 `/glebot/`（Googlebot）扩成 `/(gle|ing)bot/`（加 Bingbot）——爬虫没有视口概念，直接全部揭幕喂给它（SEO 的饭碗）；
- 302 行：`lowRuns = -1`（v1 是 0）——off-by-one 边界修补，成熟期的代码大半是这样的小数点战争；
- 507 行：`elem.complete && elem.naturalWidth > 1`——判定「图真的加载成功」加宽为「有实际宽度」，躲开缓存返回 0 尺寸图的浏览器怪癖。

## 三、配置面变化（243-267 行）

新增 `loadHidden`、`ricTimeout`、`throttleDelay` 三个键；expFactor 从 1.7 调 1.5；expand 档位简化为两档（500/370）。**配置项的数量就是库的年龄**——每项都是某类用户的真实诉求沉淀。

## 四、初始化的收尾变化（601-606 行）

v1 结尾是 `throttledCheckElements(...)`（走节流，首屏检查要等空闲）；这版是 `checkElements() + rAF._lsFlush()`——**首屏直通、立即渲染**，之后的滚动才进节流管道。首屏体验与滚动性能分开对待。
