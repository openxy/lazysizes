# 末版：类型注解收官

## 本版本引入的概念

**类型注解收官**：项目最后一个 tag 的主要增量是 JSDoc 类型注释（`@typedef`、`@type`、`@param`）——没有新机制、没有新插件，维护期的活儿变成写文档。代码定格在这个状态：一个曾经每周发版的库，最后几次提交是在给后人（和编辑器）留路标。

**缓存标记**：`fastLoadedClass: 'ls-is-cached'`（配置新增）——从缓存秒回的图也挂个类，让 CSS 特效可以区分「真加载」与「缓存命中」；`iframeLoadMode` 给 iframe 揭幕方式留最后一点控制。小而务实的收尾。

## 弧线收束（整个案例集的终点）

| 案例 | 上游区间 | 里程碑 |
|---|---|---|
| polling | 1.x（2015） | 手写实现：事件 + 节流 + 全量扫描 |
| mature | 2.x–4.x（2016-17） | 调度成熟：rIC/rAF/防抖转正；IO 版停在 src/ 实验位 |
| native | 5.x（2018-19） | 平台收编：让位协议、兼容长尾、类型收官 |

一条完整的技术普及弧线：**手写实现 → 库繁荣（生态、调度、兼容面）→ 平台原生 → 库退役**。三个案例 = 三个里程碑，每个里程碑内用版本 diff 看演进，里程碑之间靠解读叙述衔接——因为跨越架构边界的 diff 噪声太大，不适合教学（这也是「按里程碑拆案例」的原因：真实项目提交极多，拆开防止单案例版本爆炸，边界放在架构切换处正好让 diff 始终可教）。

注意中间那步「IO 实验未转正」：等浏览器把 IntersectionObserver 补齐的时候，平台顺手把懒加载整个做掉了。**技术普及的最后一跳可以跳过所有中间态**——这也是判断「会不会被平台吸收」时最该想到的反直觉事实。

## 怎么学这个版本

差异面板对照上一版看 JSDoc 补注的形态（`/** @type ... */` 遍布配置对象），体会「维护期 = 写文档」；然后回看整个案例集：从 polling/core 的 667 行到这里的 760 行，四年间核心机制只换过一次调度层。

## 思考题

- JSDoc 注释对运行时零影响，为什么维护期项目反而优先补它？（编辑器提示、下游 dts 生成、交接成本）
- 如果你是维护者，2021 年后还会接受什么 PR？（对照：上游仓库最后的提交都长什么样）
- 用本案例集的三条「被吸收信号」分析你正在用的某个库：它站在弧线的哪一段？
