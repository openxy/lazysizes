# 空闲调度转正

## 本版本引入的概念

**requestIdleCallback 转正**：polling 案例里躺了多个版本的注释草稿，在这版成为正式 throttle（`lazysizes.js` 的 throttle 段）——「检查元素」从「到点就跑」变成「浏览器空闲时跑」。滚动是渲染关键路径，检查工作插进空闲时段，主线程忙时不添乱。

**防抖（debounce）收编**：polling 末版另一段注释草稿（防抖版 onload）也转正——「停滚 99ms 后才升档预载」的语义从手搓定时器换成 debounce，一句话就对了。

**拉变推的前半步**：注意这是**调度层**的演进，不是架构革命——事件轮询还是轮询，只是执行时机从定时器换到空闲回调。架构级的新发动机（IntersectionObserver）在 mature 案例末版的 src/ 实验变体里。

## 本版本的改动（差异面板对照 polling/umd-split）

跨案例对照（上一案例末版 1.5.0 → 本版 2.0.0）：核心文件约 445 行变动，本案例最大的一个 diff，按三块读：

1. **throttle 重写**：rIC 分支成为主路径（空闲窗口 125ms、超时兜底 999ms、isPriority 提级压到 33ms）；rAF 与 setTimeout 的嵌套关系理顺；
2. **onload 重写**：loadMode 升降档换 debounce；后台标签页分支保留并加强；
3. **rAF 批处理**：rafBatch 从 unveil 内部的小工具升为全局设施（这版还是单队列，双队列要到下一版）。

另注意 diff 里大块「删除」：1.x 里那两段注释草稿**删除了**——草稿变成了正文，注释自然就不需要了。读 diff 时先看删掉的注释块，再看对应位置的新正文，这是「转正」二字的字面证据。
